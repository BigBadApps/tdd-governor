## Surprises / deviations from plan
- Plan deviation: the governor is cloned to `$RUNNER_TEMP/governor`, not `.governor-tool/` in the workspace. Playground's vitest has no `include`, so a nested checkout would have exposed the governor's own tests to the client's test run. The spec and template were amended together in `0360f68`.
- A fresh worktree has no `dist/`, so the vitest reporter is inactive and the first red run is not recorded; the hook then blocks with "never seen failing". Run `npm run build` in a new worktree before the first red.
- red-before-green misattributed lines appended to an existing test file to the last test in that file (known gap G8, span inference), blocking the commit. Workaround used: put new blocks in their own `describe` ahead of the existing ones. Expect this whenever a task appends tests to an existing file.
- diff-audit false positive: an `it.skip(` inside a STRING LITERAL in a test file (a fixture) matches the skip pattern and blocks the commit. Workaround: build the fixture line by interpolation. This is a real governor bug (the audit is regex-based, not AST-based). Log it as a new gap.
- Stub wiring can make a "first red" partial: the `--base`-without-value test passed at once because the usage guard was wired in the same step as the stub. The implementer disabled the guard once to record that test's red. Plan wording "all six fail" was unsatisfiable as ordered.
- The whole-branch review found two Important issues that per-task reviews missed: the `ciBase` precedence tests could not distinguish the three sources (the shipped workflow uses the env path only), and the template omitted the Stryker prerequisite (a client without Stryker gets GATE_UNAVAILABLE on every PR). Both fixed in `2d2233b`. The "clean diff" e2e also asserted `[PASS] mutation` when the gate was disabled; it now asserts the disabled warning.
- Playground's SonarCloud check failed on PR #14 and PR #15 ("C Security Rating on New Code", required >= A). The only new files were the workflow and a config change, so the workflow is the likely trigger. The rule was not read (private project). It is separate from the governor gate.
- The spec's Known limits stand: a PR can edit its own workflow or `.governor/config.json`.

## Deferred

- Resolve the SonarCloud finding on Playground (rule unknown; user has the link). `deferred`
- Read `.governor/config.json` from the base ref instead of the PR, so a PR cannot disable the mutation gate for itself. `deferred`
- Fork and Dependabot PRs have no access to `GOVERNOR_READ_TOKEN`, so the job fails for them. `deferred`
- Bumping the pinned governor SHA in each client is manual. The read token expires 2027-09-20. `deferred`
- diff-audit false positive on `.skip(` inside string literals (needs an AST-based check or an ignore for fixtures). `deferred`
- `ciBase` drops git's stderr in its error message; `--base=main` and typo'd flags are silently ignored (fail-safe: falls back to the default base); no e2e case for the `GITHUB_BASE_REF` path (unit-covered). `deferred`
